# Creative Factory

Работающий локальный браузерный прототип виртуального завода. React + TypeScript + Phaser; одна ортогональная карта 2048 × 1536 px, центральный холл, коридоры и четыре цеха: дизайн, медиа, текстиль, архитектура. Управляемый персонаж, четыре направления idle/walk, коллизии, следящая камера и навигационные ориентиры. Вся графика создана специально для проекта.

## Запуск

Нужны Node.js **24** (проверено 24.19.0) и npm **11** (проверено 11.9.0).

```sh
cd CREATIVE_HUB
npm ci
npm run dev
```

Откройте в браузере `http://localhost:5173` **на том же компьютере, где выполняется `npm run dev`**. Адрес localhost из облачной среды нельзя открыть на своём компьютере напрямую; для доступа по обычной ссылке используйте GitHub Pages (см. ниже). Никакие ключи, Supabase, Docker или game server для этой игры пока не нужны. `npm run dev` проверяет карту и собирает контент автоматически. Порт фиксирован: если 5173 занят, остановите другой процесс либо укажите другой порт в `apps/web/vite.config.ts`.

Нажмите на карту и перемещайтесь **WASD / стрелками**. Входы в цеха — разрывы стен с цветным порогом. Текущее пространство показывается над картой. Кнопка цеха отмечает его вход; это ориентир для самостоятельной прогулки, не телепорт. «Весь завод» переключает обзор на полный план; «К персонажу» возвращает следящую камеру. При работе с кнопками/потере фокуса движение останавливается; клик по карте возвращает управление. На этом этапе поддерживается клавиатура, сенсорный джойстик не реализован.

Приложение проверяет SHA-256 контента через Web Crypto; используйте **localhost или HTTPS**. Открывать `index.html` напрямую через `file://` нельзя.

## GitHub Pages: открытие по обычной ссылке

Публичный адрес проекта: `https://messagetomedium.github.io/CREATIVE_HUB/`.

Для текущей публикации из **main → / (root)** в репозиторий включены управляемые файлы `index.html`, `.nojekyll` и каталог `site/` с готовой статической игрой. Корневой HTML загружает приложение, не перенаправляя пользователя на README. Его ресурсы находятся под `/CREATIVE_HUB/site/`; вложенный адрес `/CREATIVE_HUB/site/` также работает.

После изменения приложения перед push обновите эту версию:

```sh
npm ci
npm run export:pages
```

Команда проверяет типы, собирает web и обновляет только собственные файлы экспорта. Каталог `site/` — генерируемый результат: править игру нужно в `apps/web`, `packages` и `content`, затем повторять экспорт. Не редактируйте сгенерированные JS/CSS вручную. Для переименованного репозитория можно задать `PAGES_BASE_PATH=/имя-репозитория/` при экспорте.

Дополнительно сохранён workflow [.github/workflows/pages.yml](.github/workflows/pages.yml) для публикации артефакта через **GitHub Actions**. Он выполняет тот же `export:pages` и публикует только web-артефакт `dist/pages` с такой же структурой `index.html` + `site/`. Это альтернативный способ: при выборе Source = GitHub Actions готовый артефакт работает по тому же публичному адресу. Оба варианта публикуют игру, поэтому стандартная branch-сборка больше не сможет заменить её страницей README.

Для сборки артефакта обоих вариантов публикации:

```sh
npm run export:pages
```

Для локальной проверки разместите содержимое `dist/pages` под `/CREATIVE_HUB/` обычного HTTP-сервера. Разработка через `npm run dev` продолжает работать от `/`. Запуск команды или push ещё не подтверждает успешный deployment: проверьте результат в Actions.

Текущая однопользовательская игра работает на статическом хостинге по HTTPS. Supabase будет внешним сервисом для аккаунтов, а Colyseus — отдельным сервером для будущего мультиплеера; GitHub Pages не запускает Node.js-сервер.

## Проверки и production build

```sh
npm run content:build
npm run typecheck
npm test
npm run build
npm run preview
```

После `preview` откройте `http://localhost:4173`. Production web находится в `apps/web/dist`; стенд совместимости сервера компилируется в `apps/game-server/dist`.

```sh
# Если Chromium не установлен:
npx playwright install chromium
npm run test:e2e
npm run format:check
```

E2E использует системный `/usr/bin/chromium`, если он есть, иначе браузер Playwright. Для другого Chromium можно задать `CHROMIUM_PATH`. В облачной машине проверено на системном Chromium 154 с Canvas-рендерером Phaser. Тест допускает до 20 секунд на загрузку; это не измерение production-производительности. Скриншоты проверок сохраняются в `.cache/review`, ошибки и traces — в `test-results`.

## Структура

| Путь                     | Назначение                                                                                              |
| ------------------------ | ------------------------------------------------------------------------------------------------------- |
| `apps/web`               | React shell, Phaser scene, обработчик клавиатуры и заменяемый поставщик временной графики               |
| `apps/game-server`       | Изолированный loopback-стенд проверки Colyseus, **не** игровой backend                                  |
| `packages/contracts`     | Валидируемые модели карты, цехов, внешности и границы будущих адаптеров                                 |
| `packages/world-core`    | Фиксированный шаг 30 Hz, нормализация диагоналей, AABB/grid-коллизии и определение зоны; без Phaser/DOM |
| `packages/content-tools` | Подготовка Tiled-карты, валидация и immutable content с SHA-256                                         |
| `content/maps`           | Собственная Tiled JSON-карта `factory.tmj`, список подключаемых цехов и SVG-tileset                     |
| `content/avatars`        | Каталог частей, палитра, preset, версии/revision, кадры анимаций и источник spritesheet                 |
| `tests/e2e`              | Настоящая браузерная проверка движения, коллизий, камеры, навигации, фокуса и ошибок контента           |

Каркас следует [архитектуре](docs/architecture.md). `supabase/migrations` и `tests/load` будут созданы с реальными миграциями/нагрузочными сценариями соответствующих этапов; фиктивных файлов для них нет.

## Как менять контент

Редактируйте `content/maps/factory.tmj` в Tiled. Поддерживается конечная orthogonal-карта с клеткой 32 px, встроенными tileset metadata, числовыми несжатыми tile layers `ground`/`solids` и прямоугольными object layers `world-props`, `interactions`, `spawns`. Rotated objects, infinite/chunked карты и внешние TSX пока намеренно отклоняются. Стена — непустая клетка `solids`; объект с `solid: true` блокирует свой прямоугольник. Вход `entrance` должен оставаться проходимым.

Имена/описания/цвета и дисциплины цехов находятся в `workshops.json`; зона с соответствующим id — в `interactions`. Для нового цеха добавьте определение, проходимую область, вход и zoneId в карту. Геометрия и визуальные объекты — данные, не условия внутри movement solver. Карточки, карта-навигатор и названия зон строятся из этих данных.

`npm run content:build` **не перезаписывает** исходную карту: он валидирует её и обновляет `apps/web/public/content`. После правок карты выполните эту команду и перезагрузите страницу. `npm run content:author` — вспомогательная генерация исходного демонстрационного layout; она **перезаписывает `factory.tmj`**, поэтому запускайте её только при намеренном восстановлении/перегенерации layout.

Временный персонаж создаётся `placeholderArt.ts` по `catalog.json`. Для настоящей графики задайте `sprite.source.kind = "spritesheet"`, URL своего атласа, размеры и semantic frame mapping idle/walk для четырёх направлений. Движение от этих деталей не зависит. Предметы используют `assetId` и отдельный поставщик графики `makeProp`; переход на собственные изображения потребует поменять этот provider/каталог, но не физику, карту препятствий или ввод. Редактор внешности с сохранением относится к следующему этапу; сейчас подготовлена его модель данных.

## Стенд Colyseus

`npm test` поднимает сервер на свободном порту **127.0.0.1**, подключает два реальных SDK-клиента и проверяет initial state, patches, callbacks, StateView-фильтрацию, удаление при drop, reconnect и окончательный leave. Видимый игрок удаляется до начала grace period, приватно сохраняется позиция. Самостоятельно стенд можно запустить `npm run dev:spike` (127.0.0.1:2567), либо после сборки `node apps/game-server/dist/index.js`.

Это технологическая проверка этапа 1 без Auth, production admission и серверной игровой физики. Браузерный прототип к ней не подключается. API, подтверждённые тестом: `schema()`/`t.*`, `StateView.add/remove`, `getStateCallbacks`, `onDrop`, `allowReconnection`, `onReconnect`, `onLeave`. У SDK automatic reconnect включён по умолчанию; в тесте он отключён, чтобы отдельно наблюдать исчезновение и явное восстановление. Перенос этих возможностей в продукт выполняется на этапах 4–6 после Auth.
