# Статус первого технического прототипа

23 октября 2026 года. Этот документ дополняет исходные [архитектуру](architecture.md) и [план](implementation-plan.md), не заменяя их.

## Уточнение объёма по запросу на реализацию

В первоначальном плане этап 1 — технический каркас и проверка стека, а подробная локальная карта/анимации относятся к этапу 3. Пользователь отдельно включил их в текущую задачу. Поэтому реализованы каркас и изолированный Colyseus compatibility spike этапа 1, а также локальная визуальная часть этапа 3. Auth, аккаунты, сохранение внешности и игровой мультиплеер вперёд не перенесены. Весь этап 3 и тем более MVP не объявляются завершёнными.

Архитектура сохранена: React — редкие UI-события, Phaser — отображение, чистый `world-core` — фиксированный шаг и коллизии, content pipeline — независимые данные и графика. Пока симуляция вызывается локально. На этапе 4 ту же функцию должен вызывать авторитетный Colyseus server; нынешний локальный режим не доказывает серверную безопасность будущей игры.

Выбран Phaser 3.90.0 с Canvas-рендерером и проверенными API tilemap и анимаций. Шейдеры текущей сцене не нужны; карты, физика и каталог графики от выбора renderer не зависят. Упомянутый в аудите Phaser 4.2.0 был версией референса, а не обязательным требованием нашего проекта. React 19.3.1, TypeScript 5.9.3, Vite 8.3.5; Node.js 24.19.0, npm 11.9.0. Server/schema/SDK Colyseus закреплены совместимыми версиями в package-lock.json.

## Что создано

- Один браузерный персонаж, одна ортогональная Tiled JSON-карта 64 × 48 клеток по 32 px, холл, коридоры, четыре цеха.
- Собственный SVG-tileset и процедурная 2D-графика персонажа/предметов; геометрия отделена от поставщика изображений.
- WASD/стрелки, нормализация диагоналей, idle/walk четырёх направлений, фиксированный шаг 30 Hz с визуальным сглаживанием.
- Grid/AABB-коллизии со стенами и 30 статическими предметами; подшаги для тонких препятствий, ограничения границ мира.
- Следящая камера с границами, обзор всего завода, выбор ориентира на вход цеха, текущая зона и мини-карта.
- Непокадровый React-мост; позиция мини-карты обновляется императивно с ограниченной частотой. Ввод очищается при потере фокуса/видимости.
- Валидируемые структуры avatar parts/palette/preset/revision и реестр подключаемых цехов; отображение и физика не зависят от будущих имён графических файлов.
- Валидация исходной карты, SHA-256 контента, immutable filenames, реестр происхождения/контрольных сумм собственной графики.
- Отдельный loopback-стенд Colyseus: initial state, patches, callbacks, StateView, drop/reconnect/leave. Он не подключён к игровому UI и не является production backend.
- Lockfile, команды разработки/сборки/проверки, CI workflow, README и перечень прямых лицензий.

## Как проверять

Точные команды находятся в [README](../README.md). `npm test` включает настоящие подключения к серверу на 127.0.0.1, а `npm run test:e2e` — управление настоящим Chromium, не подмену Phaser.

Браузерный набор проверяет отображение/анимацию, один canvas при StrictMode, WASD/стрелки, потерю фокуса, проход через дверь в цех, столкновения со стеной/скамьёй, следящую камеру и её границы, overview/resize, ошибку checksum и очистку canvas при недоступном tileset. Unit-тесты отдельно проверяют диагонали, препятствия, тонкие объекты, невалидный spawn, приоритет зон и связность всех цехов. Финальная проверка 23 октября 2026 года:

| Проверка                                    | Результат                                                                                                   |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Чистый `npm ci`                             | Успешно; SHA-256 lockfile до и после совпал                                                                 |
| `npm run typecheck`, `npm run format:check` | Пройдены                                                                                                    |
| `npm test`                                  | 15/15: 14 проверок ядра/контента и один интеграционный сценарий с двумя Colyseus-клиентами                  |
| `npm run test:e2e`                          | 7/7 в Chromium 154; JS-ошибок в финальном прогоне нет                                                       |
| `npm run build`                             | Web и серверный стенд собраны; известное предупреждение о размере Phaser chunk                              |
| Production preview                          | Браузером проверены canvas, движение и переход в цех; development API отсутствует, license notices доступны |
| Собранный сервер                            | Запущен обычным Node.js; SDK-клиент получил state и выполнил leave                                          |

Браузерные сценарии выполнялись в headless Chromium на Linux с Canvas-рендерером, основным viewport 1440 × 1000 и resize до 1000 × 800. Проверялся один персонаж, карта 64 × 48 и 30 статических предметов; результаты не экстраполируются на мультиплеерную нагрузку.

Первичная проверка браузером обнаружила ошибку разбиения процедурного CanvasTexture на кадры; она исправлена явным добавлением кадров через Texture API. Изолированный тест соединения также исправлен на допустимый для браузерного WebSocket application close code; семантика drop и проверки видимого состояния сохранены.

При расширенной проверке resize обнаружился нестабильный сбой WebGL framebuffer в программном рендерере облачного Chromium. Для этого простого 2D-прототипа выбран штатный Canvas-рендерер Phaser; ошибки браузера проверяются в каждом E2E-сценарии. Если позже потребуется WebGL, его нужно отдельно проверить на целевых устройствах. Обзорный план также исправлен: ограничение камеры временно снимается для центрирования всей карты и восстанавливается в режиме следования.

## Ограничения

Это локальный технический прототип. Нет регистрации, настоящих профилей, редактора внешности с сохранением, NPC, серверного игрового состояния, дистанционных игроков, переходов между отдельными картами или сенсорного управления. Готовы данные и границы модулей, а не эти будущие функции.

Измерения вместимости/50–100 пользователей и production FPS не проводились. Canvas-рендеринг в облачном Chromium не является проверкой производительности будущего WebGL-клиента. Firefox/Safari пока не проверялись. Кнопка обзорного плана специально показывает карту целиком с нейтральным фоном; ограничение камеры внутри мира применяется в режиме следования.

Сборка предупреждает о размере Phaser chunk: примерно 1.19 MB minified / 318 KB gzip. Движок вынесен в отдельный динамически загружаемый chunk; предупреждение не скрывается. Для текущего прототипа это известное ограничение начальной загрузки, не ошибка сборки.

Текущий графический набор — временный. До замены на настоящие ассеты проверить их права и добавить provenance. Полноценная карта со сложными высокими объектами/overhead и редактированием внешности должна пройти расширенные проверки этапа 3 после этапа 2.

## Публикация GitHub Pages

Первоначальный workflow публиковал только сборку через GitHub Actions. При включённом источнике **main → / (root)** стандартная branch-публикация вместо игры показывала README: в корне не было `index.html`.

Исправление от 26 октября 2026 года добавляет управляемые `index.html`, `.nojekyll`, `site/` и команду `npm run export:pages`. Корневая страница сразу монтирует приложение; ресурсы берутся из `/CREATIVE_HUB/site/`. Веточная публикация и Actions теперь используют одинаковую структуру; артефакт Actions — `dist/pages`. Переключать источник Pages для этой версии не требуется. После изменения исходников перед push нужно повторить экспорт; вручную редактировать `site/` не следует.

После изменения прошли проверка типов, сборка, форматирование и 26 тестов. Статический артефакт проверен в Chromium по корневому адресу `/CREATIVE_HUB/`: один canvas, загрузка всех ресурсов, управление, переход в цех, обзор и перезагрузка через вложенную стартовую страницу. HTTP- и JavaScript-ошибок в проверке нет. Публичный домен github.io по-прежнему недоступен из облачной среды из-за сетевого прокси; результат фактической публикации проверяется по GitHub Actions.
