# Статус Creative Factory

26 октября 2026 года. Документ дополняет утверждённые [архитектуру](architecture.md) и [план](implementation-plan.md). Прежний локальный Phaser-прототип сохранён; вокруг него реализован код пользовательского этапа 2.

## Что работает в коде

- Отдельные React-экраны: главная, вход, кабинет, редактор и завод. Hash routing работает в `/CREATIVE_HUB/` и `/CREATIVE_HUB/site/` без server rewrite; защищённые экраны направляют на вход, неизвестный адрес показывает понятную страницу.
- На главной после входа — завод, персонаж и две явно обозначенные заглушки «Скоро»: эксперты ККИ/события. В шапке имя, кабинет и logout. Айдентика прежняя: тёплый фон, зелёный/лаймовый, собственная SVG-иллюстрация.
- Реальный адаптер `@supabase/supabase-js`: Email OTP через `signInWithOtp`/`verifyOtp`, регистрация и повторный вход одним flow, сохранение/refresh сессии SDK, logout, таймер кода и resend, состояния загрузки/ошибок. Постоянных цифровых паролей нет.
- Если URL/publishable key не настроены, вход явно недоступен. Никаких тестовых пользователей/кодов, mock backend или обхода входа в production нет. Главная и прежняя локальная прогулка остаются доступными без аккаунта.
- Профиль: обязательные имя/фамилия, роль эксперт/педагог, специализация, организация, до 16 компетенций, bio до 1000 символов и до 5 HTTPS-ссылок. Лимиты, протоколы ссылок и управляющие символы проверяются в TypeScript и SQL. Роль — профессия, не административное разрешение; имя не является ключом.
- Настоящая миграция `profiles`, `profile_private`, `avatar_configs`, RLS, ограниченные grants, invoker RPC и revision triggers. Email остаётся только в Auth, `user_id` ссылается на Auth UUID, private-строки доступны только владельцу. Сохранения со старой revision отклоняются; UI предлагает загрузить сохранённую версию.
- Редактор: 2 тела, 3 причёски, 3 вида одежды, наушники/без аксессуара, 4 независимых цвета (включая обувь), крупный предпросмотр и четыре направления. Все варианты — собственная различимая временная графика.
- Общий `avatar/art.ts` рисует и предпросмотр, и Phaser spritesheet. Сохранённая внешность передаётся в сцену при входе; редактор сохраняет в Supabase и восстанавливает конфиг при следующей загрузке аккаунта. Прямое готовое spritesheet пока не является системой многослойных атласов: для настоящих частей понадобится новый provider с теми же контрактами.
- Phaser создаётся только на экране завода и уничтожается при уходе/выходе из аккаунта, включая нормальный logout в соседней вкладке. Защита от запоздалой lazy-загрузки и React StrictMode сохранена; старые запросы аккаунта не заменяют данные следующего пользователя.
- Обновлены `.env.example`, Pages workflow, provenance и runtime license notices. [Инструкция Supabase](supabase-setup.md) описывает миграцию, Email Templates с `{{ .Token }}`, custom SMTP, параметры и ручную приёмку.

## Что сохранено от первого этапа

Не изменены `world-core`, обработчик движения, геометрия Tiled-карты, коллизии, скорость, fixed tick 30 Hz, следящая камера, обзор и мини-карта. Завод по-прежнему строго top-down: 64 × 48 клеток по 32 px, холл, коридоры, четыре цеха и 30 статических предметов. Клиентская симуляция локальная. Colyseus остаётся изолированным loopback-стендом, не игровым backend; других участников на карте нет.

React хранит редкие UI-события; позиция мини-карты обновляется через мост без покадрового React state. Фокус/blur/visibility останавливают ввод. Контент валидируется и сверяется SHA-256. Phaser 3.90.0 Canvas выбран ранее из-за нестабильного software WebGL framebuffer при resize в облачном Chromium; renderer на этом этапе не менялся.

Проверки выполняются на Node.js 24.19.0 / npm 11.9.0, Linux, системный Chromium 154. Основной viewport 1440 × 1000; проверяется также 390 × 844. Команды — в [README](../README.md).

- `npm test`: **52/52**, восемь файлов. Включены прежние core/content/Colyseus проверки, валидация данных/публичной конфигурации/маршрутов и семь интеграционных сценариев настоящей миграции в PostgreSQL WASM (PGlite).
- SQL-набор запускает политику под ролями anon/A/B: публичное чтение зарегистрированными, изоляция private, отказ чужих INSERT/UPDATE/user_id, отсутствие административной роли/email, revision conflicts, ограничения полей, HTTPS и неизвестных частей аватара. `auth.uid()` в стенде моделируется контролируемым claim; GoTrue/JWT validation hosted Supabase этим не проверяется.
- Chromium E2E используют настоящий SDK с контролируемыми HTTP-ответами только внутри тестов: первый/повторный вход, профиль, изображение и сохранение аватара, reload, OTP error/expiry/resend/rate limit, конфликт revision, недоступная БД, logout/соседняя вкладка и очистка Phaser. Это не проверка доставки email.
- Семь прежних игровых E2E сохранены. Меняется только стартовый адрес на `/#/factory`, потому что `/` теперь настоящая главная. Проверяются движение/анимация/коллизии/камера/фокус/resize/checksum/loading errors.

## Ручные настройки и ограничения

**Supabase-проект пока не создан**, по ответу владельца. Код готов к подключению, но реальное создание аккаунтов, доставка писем, SMTP DNS, hosted RLS с JWT A/B и сохранение в удалённой БД не проверены. Это незакрытые критерии приёмки этапа 2, а не подтверждённая работа внешних сервисов. Следуйте [supabase-setup.md](supabase-setup.md), затем выполните приёмку двух настоящих пользователей.

В web используются только publishable key и пользовательские JWT. Build отклоняет private/legacy key в поле publishable key; URL должен быть HTTPS (loopback HTTP разрешён только в dev). Приложение не логирует email/OTP/JWT/данные форм. SDK сохраняет токены в localStorage; на общем компьютере нужно выходить из аккаунта. При сетевой ошибке logout локальная сессия очищается и SDK перезапускается; отзыв refresh token на сервере требует доступного Auth, а выданный access JWT живёт до своего expiry.

Полного мультиплеера, присутствия других пользователей, профилей из мира, NPC, автономной жизни и сенсорного джойстика нет. Эксперты/события — заглушки. `profile_private` содержит locale без отдельного UI; загрузок файлов в Storage нет. Нет измерений production FPS/вместимости, Firefox и Safari пока не проверены. Предупреждение о размере Phaser chunk остаётся известным ограничением, не скрывается.

## Публикация GitHub Pages

Сохраняется исправленная схема: управляемые корневые `index.html`/`.nojekyll`, собранный `site/`, команда `npm run export:pages`, Actions artifact `dist/pages`. И branch source main/root, и Actions открывают приложение. Настройки Auth фиксируются в конкретной сборке: Repository Variables влияют на Actions-экспорт, локальный `.env` — на локальный branch-экспорт. На этом шаге публикуется версия без параметров Supabase: главная/прогулка работают, вход честно отключён.

Публичный домен github.io недоступен из облачной среды из-за сетевого прокси. Локальная браузерная проверка точного статического артефакта и статус GitHub workflow — доступные способы проверки; они не подменяют наблюдение реальной доставки email.
