# ТЗ на заменяемую графику Creative Factory — 3/4 top-down

**Дополнение конструктора 27 октября:** ниже описан прежний минимальный набор болванок. Новые слоты тела/головы/одежды/деталей и требования к мини-иконкам зафиксированы в [avatar-constructor.md](avatar-constructor.md). Все они сохраняют кадр 48×64 / лист 288×256, но для полной графики новых слотов нужно расширить manifest/provider; старые 16 PNG не покрывают весь новый конструктор.

27 октября 2026 года. Это техническое задание художнику и инструкция подключения к уже реализованным болванкам. Нужен собственный рисунок, без копирования спрайтов Stardew Valley, WorkAdventure и сторонних наборов без разрешения.

## Ракурс и объём

Условный ортографический **3/4 top-down**: видны верхние поверхности и обращённые к зрителю фасады; у персонажа видны лицо/спина/профиль. Персонаж всегда стоит вертикально, не вращается как фишка. Направление камеры — с юга карты; вертикали рисунка параллельны. Не использовать изометрические ромбы, перспективное схождение линий или наклонять всю карту.

Пол остаётся сеткой **32 × 32 px**, мир — **2048 × 1536 px**. Координаты, двери, стены, хитбоксы и движение не меняются. Изображение может подниматься над своей опорной областью; высота рисунка не добавляет препятствий. Камера работает в прежнем масштабе около 1:1; персонаж имеет видимую высоту примерно 48–52 px.

Сейчас нужны простые заменяемые формы. Не нужны новые комнаты/объекты, NPC, окружение с мелким декором, частицы, освещение, normal maps, анимации станков, новые эмоции или восемь направлений персонажа. В мире уже есть 30 экземпляров предметов: они используют 10 повторяемых форм, а не 30 уникальных рисунков.

## Общие требования к файлам

- Игровой экспорт — **PNG RGBA, 8 бит на канал, прозрачный фон, sRGB, масштаб 1×**. PNG каждого листа имеет ровно указанные ниже размеры. JPEG/WebP/SVG для этих замен не использовать.
- Без trim, поворота кадров, автоматической упаковки, полей между ячейками и добавочного extrusion. Пустые участки внутри кадра прозрачны; полностью пустые резервные ячейки сохраняются.
- Не запекать подписи цехов, интерфейс, маркеры и тени в рисунок. Тени/кольцо персонажа и тексты создаёт сцена отдельно. Не использовать фон цвета «под прозрачность».
- Во всех направлениях и кадрах сохранять общий размер, ноги и контакт с полом; не центрировать каждый рисунок автоматически. Согласованные точки опоры важнее плотной упаковки листа.
- Для линий и мелких деталей ориентироваться на целые пиксели. Тестирование текущих болванок использует Canvas; не закладывать обязательные шейдеры.
- Передать также редактируемые исходники `.aseprite` / `.psd` / аналог, автора, лицензию/договор, дату и список файлов. Права на использование и распространение должны включать приложение и публичный репозиторий. Это записывается в `content/ASSETS.md`.

## Список поставки

| Набор           | Размер одного кадра | Сетка / размер PNG                    | Число файлов для текущего каталога                                       |
| --------------- | ------------------- | ------------------------------------- | ------------------------------------------------------------------------ |
| Части персонажа | **48 × 64**         | 6 столбцов × 4 строки / **288 × 256** | **13**: 2 тела + 6 комплектов одежды + 3 причёски + 1 обувь + 1 наушники |
| Предметы        | **160 × 128**       | 4 × 3 / **640 × 384**                 | **1**, 10 используемых ячеек + 2 резервные                               |
| Стены           | **32 × 64**         | 4 × 1 / **128 × 64**                  | **1**, четыре окончания стены                                            |
| Пол             | **32 × 32**         | 8 × 1 / **256 × 32**                  | **1**, шесть основных плиток + две служебные                             |

Итого для полной замены **16 PNG**. Пол можно заменить последним: нынешние плоские плитки уже совместимы с новым ракурсом. Никаких дополнительных декоративных спрайт-листов сейчас не требуется. Начать согласование удобно с одной собранной фигуры, одного стола и одного фрагмента стены, затем применить тот же язык к остальным ячейкам.

## Персонаж: точная раскладка

Кадр **48 × 64 px**, точка ног **(24, 56)** от левого верхнего угла. В Phaser это origin **(0.5, 0.875)**. Базовая линия подошвы — y=56, снизу остаются 8 прозрачных пикселей. Рекомендуемые границы рисунка: x=7…41, y=3…56. Не обрезать наушники и кудри; не перемещать anchor при расширении причёски.

Физический хитбокс остаётся **20 × 16 px** вокруг точки ног. Широкое тело увеличивает только рисунок, не скорость и не коллизии. Восемь диагональных направлений не нужны: при движении по диагонали сохраняется существующий выбор одного из четырёх направлений.

| Строка       | Направление | Содержание         |
| ------------ | ----------- | ------------------ |
| 0, y=0…63    | north / ↑   | Спина и затылок    |
| 1, y=64…127  | east / →    | Правый профиль     |
| 2, y=128…191 | south / ↓   | Лицо, перед одежды |
| 3, y=192…255 | west / ←    | Левый профиль      |

| Столбец | x начала кадра | Поза                                              |
| ------- | -------------- | ------------------------------------------------- |
| 0       | 0              | idle A                                            |
| 1       | 48             | idle B, небольшое дыхание, ноги остаются на опоре |
| 2       | 96             | walk A, нейтральная фаза                          |
| 3       | 144            | walk B, шаг первой ногой                          |
| 4       | 192            | walk C, нейтральная фаза                          |
| 5       | 240            | walk D, шаг второй ногой                          |

Номер кадра: `строка × 6 + столбец`. Idle играет кадры `[0,1]` своей строки на **2 fps**, walk `[2,3,4,5]` — **9 fps**. Все части обязаны совпадать по позе, движению рук, дыханию, направлению и фазе. В одном PNG нельзя смешивать разные точки опоры. Левый профиль можно нарисовать отражением правого, но в поставке нужна полноценная четвёртая строка; движок не поворачивает северный рисунок на 90°.

### Части, цвета и имена файлов

Полный готовый пример `sprite.source` находится в [avatar-layered.example.json](../content/art/avatar-layered.example.json). В нём **13** записей с точными именами PNG и связями вариантов. Все эти PNG имеют одинаковые **288 × 256** и полностью прозрачные ненужные участки кадра.

| Группа    | Файлы / варианты                                                                          | Что рисовать                                                                                                                                         |
| --------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Тело      | `avatar-body-base-01-v1.png`, `avatar-body-base-02-v1.png`                                | Обычное и широкое тело: кожа головы, шеи, рук; лицо. Голова в той же позиции у обоих тел                                                             |
| Обувь     | `avatar-shoes-v1.png`                                                                     | Одна пара для обоих тел; соответствует всем четырём фазам ходьбы                                                                                     |
| Одежда    | `avatar-outfit-{ID}-{BODY}-v1.png`                                                        | ID: `workwear-01`, `jacket-01`, `dress-01`; BODY: `base-01`, `base-02`. Всего 6 листов. Одежда, рукава, брюки/нижняя часть; не рисовать кожу и обувь |
| Причёска  | `avatar-hair-short-01-v1.png`, `avatar-hair-bob-01-v1.png`, `avatar-hair-curls-01-v1.png` | Короткая стрижка, каре, кудри; подходят обоим телам. Не менять размер/положение головы                                                               |
| Аксессуар | `avatar-headphones-01-v1.png`                                                             | Наушники, прозрачная остальная часть. Отсутствие аксессуара — отсутствие слоя, отдельный пустой PNG не нужен                                         |

Окрашиваемые слои — **нейтральная шкала серого RGBA**: R=G=B; белое получает выбранный цвет, серое — его более тёмный оттенок, чёрное остаётся чёрным. Кожа → `palette.skin`, волосы → `palette.hair`, одежда → `palette.outfit`, обувь → `palette.shoes`. Поэтому не запекать оранжевую одежду или натуральный цвет кожи в маску. Глаза/малые линии можно оставить чёрными. Наушники — обычный готовый RGBA без перекрашивания.

Порядок композиции: **тело → обувь → одежда → волосы → наушники**. Не рисовать скрытую одеждой кожу поверх одежды. Текущие короткие причёски должны укладываться в один слой поверх тела/одежды; длинные волосы с отдельной задней частью пока не входят в ТЗ. Совмещение слоёв происходит один раз при выборе внешности, не заново на каждом игровом кадре.

`catalogVersion=1`, ID частей, palette и сохранённые конфигурации Supabase **не меняются**: меняется представление того же каталога. Новые ID/новая структура требуют отдельного согласования и DB-миграции, для замены рисунка она не нужна.

## Предметы: один лист 640 × 384

Имя: **`factory-props-v1.png`**. Ячейка **160 × 128**, anchor основания **(80,112)**. Origin `(0.5,0.875)`. Объект ставится этой точкой в **центр южной границы существующего collider rectangle**. Его depth равен Y этой границы, а не Y верхнего пикселя.

Для footprint `W × D` и визуальной высоты `H`:

- Проекция области на полу: x=`80−W/2`…`80+W/2`, y=`112−D`…`112`.
- Верхняя плоскость: x те же, y=`112−D−H`…`112−H`.
- Южный фасад: y=`112−H`…`112`. Рисунок может быть свободнее внутри той же области, но anchor и footprint сохраняются.
- Хитбокс задаётся картой, не PNG. Не расширять его из-за кроны, монитора, спинки или декоративного контура. Тень в лист не включать.

Кадры идут слева направо, затем следующая строка. Начало кадра: `x=(frame % 4)×160`, `y=floor(frame/4)×128`.

| frame | ID предмета   | Footprint W × D | Визуальная высота H | Что достаточно нарисовать              |
| ----- | ------------- | --------------- | ------------------- | -------------------------------------- |
| 0     | worktable     | 96 × 64         | 24                  | Рабочий стол, один лист на поверхности |
| 1     | console       | 96 × 64         | 24                  | Пульт/стол с простым экраном           |
| 2     | cutting-table | 96 × 64         | 24                  | Раскройный стол с цветным матом        |
| 3     | model-table   | 96 × 64         | 24                  | Макетный стол с одним простым объёмом  |
| 4     | worktable     | 128 × 64        | 24                  | Широкая версия кадра 0                 |
| 5     | console       | 128 × 64        | 24                  | Широкая версия кадра 1                 |
| 6     | cutting-table | 128 × 64        | 24                  | Широкая версия кадра 2                 |
| 7     | model-table   | 128 × 64        | 24                  | Широкая версия кадра 3                 |
| 8     | bench         | 64 × 32         | 16                  | Одна простая скамья                    |
| 9     | plant         | 32 × 32         | 32                  | Один горшок и одна простая крона       |
| 10–11 | —             | —               | —                   | Полностью прозрачный резерв            |

Повторяющиеся предметы используют эти же кадры. Не нужны отдельные PNG для каждого экземпляра или каждого цеха. Визуальные формы определены в [scene-art.json](../content/art/scene-art.json); ширины 96 и 128 намеренно не растягиваются кодом из одного рисунка, чтобы детали сохраняли масштаб.

## Стены: лист 128 × 64

Имя: **`factory-walls-v1.png`**, четыре кадра **32 × 64**, anchor **(16,64)** / origin **(0.5,1)**. Верхние 32 px — верхняя плоскость, нижние 32 — простой южный фасад. У соседних кадров край должен стыковаться без швов. Визуальная высота над footprint — 32 px.

| Кадр слева направо | Назначение                            |
| ------------------ | ------------------------------------- |
| 0                  | Середина: есть сосед слева и справа   |
| 1                  | Левое окончание: слева стены нет      |
| 2                  | Правое окончание: справа стены нет    |
| 3                  | Одиночный фрагмент: нет обоих соседей |

Стены размещаются по исходной collision grid и сортируются по нижней границе каждой клетки. Не закрашивать двери/пустые клетки. Отдельные анимации дверей, крыши и интерьерные декоративные стены пока не нужны. Это невысокие условные фасады: не поднимать их произвольно на 128 px и не скрывать всю сцену. Общего слоя «все стены поверх всех персонажей» больше нет.

## Пол: лист 256 × 32

Имя: **`factory-floors-v1.png`**. Восемь бесшовных плиток **32 × 32**, одна строка. Никаких фасадов/стен/надписей внутри пола. Можно сохранить нынешние спокойные одноцветные заливки и лёгкий общий шов.

| Кадр | Назначение                                                                |
| ---- | ------------------------------------------------------------------------- |
| 0    | Нейтральный пол                                                           |
| 1    | Холл/коридоры                                                             |
| 2    | Дизайн                                                                    |
| 3    | Медиа                                                                     |
| 4    | Текстиль                                                                  |
| 5    | Архитектура                                                               |
| 6    | Служебный резерв                                                          |
| 7    | Старый служебный маркер solids; в новой видимой сцене стенами не рисуется |

Tiled использует firstgid=1, поэтому кадр 0 PNG соответствует tile ID 1 в исходном `.tmj`. Геометрию исходного `.tmj` и размеры сетки для подстановки менять не нужно.

## Эталоны и подключение

Экспортированы **точные текущие болванки**, чтобы художник видел заполнение и прозрачные поля:

- [Персонаж 288 × 256](../content/art/reference/avatar-blockout.png) — собранный цветной пример, **не** готовый набор масок частей.
- [Предметы 640 × 384](../content/art/reference/props-blockout.png).
- [Стены 128 × 64](../content/art/reference/walls-blockout.png).
- [Координаты и раскладка](../content/art/reference/layout.json).

Они служат геометрическим эталоном, не финальной стилистикой. В production эти reference PNG не загружаются: текущие простые текстуры создаются один раз из кода. Для обновления эталонов запустите Vite (`npm run dev`), затем в другом терминале на той же машине `npm run art:reference`; можно передать адрес другого локального порта аргументом.

Когда финальные файлы готовы:

1. Поместить **16 PNG** в `content/art/`, сверить размеры и права. Имена версионировать (`v1`, затем `v2`), не заменять содержимое уже опубликованного immutable имени.
2. В `content/avatars/catalog.json` заменить **только `sprite.source`** на объект из `avatar-layered.example.json`. Параметры кадров, anchor, части и анимации оставить согласованными.
3. В `content/art/scene-art.json` для `props`, `walls`, `floors` заменить `source` на `{ "kind": "spritesheet", "url": "/content/factory-props-v1.png" }` и соответствующие имена стен/пола. Метаданные ячеек/footprint/высот сохранить.
4. Выполнить `npm run content:build`, `npm run typecheck`, `npm test`, `npm run test:e2e`, `npm run export:pages`. Pipeline копирует объявленные файлы в web-контент, а пути учитывают `/CREATIVE_HUB/site/`.
5. Проверить в редакторе все варианты, цвета и направления, затем перед/за предметом, проходы и камеру. Проверка загрузки PNG и композиции масок уже есть в E2E; отсутствие PNG или неверный размер не превращаются в тихое растяжение.

Код механики при такой поставке менять не нужно. PNG-источники выбираются каталогами; preview и игровая сцена используют один композитор. Неполную поставку нельзя объявлять готовой заменой всего редактора. Единый `spritesheet` персонажа тоже поддерживается, но он задаёт фиксированную внешность; для сохранения выбора частей нужен именно `layered-sheets`.

## Приёмка графики

- Листы имеют точные размеры, порядок и прозрачность; все варианты остаются внутри своих кадров, между кадрами нет bleed.
- Ноги стоят на одной опоре, лицо/спина/профиль различимы, ходьба всех частей синхронна. Все четыре цвета действительно меняют соответствующие части.
- При обходе предмета сверху нижняя часть персонажа скрывается за предметом; снизу персонаж перекрывает его фасад. Стены также сортируются по основанию.
- Ни один PNG не меняет существующие коллизии, двери, скорость, диагонали, spawn или зоны.
- В каталоге нет внешних URL и неизвестных IDs, а в реестре есть права на каждый файл. Новые текстуры загружаются/составляются один раз; никаких дорогих эффектов или дополнительных декоративных сущностей.
