# Локальный деморежим Creative Factory

27 октября 2026 года. Активный режим приложения временно переключён на **demo** по запросу владельца. Главная → «Войти в деморежим» → `/#/menu` с тремя карточками: персонаж, завод, кабинет-заглушка. Регистрация, email и OTP в этом режиме не используются.

## Данные и идентичность

`apps/web/src/account/demo.ts` реализует существующий AccountService. Отображаемое имя **«Администратор (демо)»** — подпись локальной тестовой сессии. Внутренний ID `local-demo` не является Supabase UUID, JWT или ролью; адаптер не создаёт токены и не вызывает Supabase/API/game server. Он не предоставляет административных прав.

Пространства localStorage:

- `creative-factory-demo-session-v1`: `{ formatVersion: 1, kind: "demo", active: true }`.
- `creative-factory-demo-avatar-v1`: `{ formatVersion: 1, avatar: AvatarConfig }`.

Выход удаляет только запись демосессии. Аватар сохраняется для следующего входа в том же браузере. Реальный ключ SDK `creative-factory-auth-v1` не читается и не изменяется демоадаптером. Тесты проверяют разделение namespaces, формат, валидацию частей/цветов, revision conflicts, повреждение и отказ хранилища.

Записи проверяются SavedAvatarSchema и текущим каталогом. Повреждённая/несовместимая внешность заменяется безопасным default, UI сообщает о восстановлении. Повреждённая сессия требует повторного входа кнопкой. Если браузер запрещает запись или исчерпана квота, интерфейс показывает ошибку, а не утверждает успешное сохранение. Изменения с устаревшей revision не перезаписывают более новую запись; можно загрузить сохранённую версию.

## Редактор и завод

Используются прежние AvatarConfig/AvatarCatalog и общий рендерер 3/4 top-down. Категории: тело, кожа, причёска, одежда, обувь, аксессуар. Есть миниатюры, независимые цвета и удаление аксессуара. Предпросмотр крупный, с целочисленным масштабированием и nearest-neighbour, поворотом в обе стороны/выбором четырёх направлений и анимациями idle/walk. Миниатюры статичны; отдельный animation loop работает только у большого preview. Лист пересобирается при изменении внешности, не на каждом кадре анимации и не при повороте.

«Случайный персонаж» выбирает только существующие IDs и цвета; «Сбросить изменения» возвращает последнюю загруженную/сохранённую конфигурацию. Сохранение явно записывает конфиг; вход на завод использует последнюю сохранённую версию. Уход с изменённой внешностью предупреждает через confirm; Back/Forward и перезагрузка также учитывают несохранённые изменения. Потеря/выход из сессии закрывает защищённые экраны.

Кабинет в демо показывает «Личный кабинет скоро появится». Настоящая форма ProfilePage сохранена и доступна в режиме Supabase. Геометрия карты, ракурс, world-core, скорость/хитбокс, коллизии, камера, мини-карта и Phaser lifecycle этим шагом не меняются. Движение локальное, общий онлайн-мир пока не подключён.

## Запуск и публикация

```sh
npm ci
npm run dev
```

Открыть `http://localhost:5173` на компьютере, где запущена команда. Переменные не обязательны: default — demo. Для GitHub Pages достаточно `npm run export:pages` и публикации готового экспорта обычным существующим способом. Источник страниц и hash routing сохраняются; прямые ссылки `/#/menu`, `/#/avatar`, `/#/profile`, `/#/factory` восстанавливают локальную сессию после reload. Без сессии защищённые страницы возвращают на старт.

В demo Vite не экспортирует Supabase-параметры в клиентскую среду, а bootstrap не создаёт SDK client. Поэтому режим работает и при отсутствующих/неправильных настройках Supabase, без обращений к нему. В Pages workflow `VITE_ACCOUNT_MODE` берётся из Repository Variable, по умолчанию `demo`.

## Возврат настоящих аккаунтов

1. В локальном `.env` установить `VITE_ACCOUNT_MODE=supabase` и заполнить публичные параметры по [supabase-setup.md](supabase-setup.md); перезапустить Vite.
2. Для Actions установить Repository Variable `VITE_ACCOUNT_MODE=supabase`, публичные URL/publishable key и пересобрать публикацию. Для branch-публикации повторить экспорт с этим режимом в локальном `.env` и отправить `site/`/корневой HTML.
3. Применять/проверять существующие миграции и SMTP по инструкции Supabase. Приёмку реальной доставки выполнить отдельно.

Supabase Auth, SQL/RLS, профессиональная форма и настоящий adapter остаются в репозитории. Демоаватары автоматически **не импортируются** в настоящие аккаунты: для такого переноса нужен отдельный явный пользовательский шаг. Переключение режима не удаляет ни один из namespaces.

## Проверки и ограничения

`npm run test:e2e` запускает два независимых стенда: demo на 5180 с намеренно неверной конфигурацией Supabase и реальный SDK adapter на 5181 с управляемыми HTTP fixtures. Демо-сценарии проверяют отсутствие Auth/Data API запросов, весь пользовательский путь, сохранение после выхода, повреждение хранилища, направления/анимации, предупреждение ухода, повторные mount/unmount и мобильную ширину. Прежние игровые и SQL/RLS тесты сохранены.

Локальные данные не синхронизируются между компьютерами/браузерами и теряются при очистке данных сайта; это тестовый режим, а не серверная авторизация или backup. Локальная сессия может быть изменена средствами браузера и не является средством защиты. Финальный пиксель-арт, мультиплеер и реальные профили демо не добавляет. Результаты прогонов — в [prototype-status.md](prototype-status.md).
