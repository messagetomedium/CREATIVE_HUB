# Утверждённый персонаж: контракт графики и границы кода

29 октября 2026. Художественная основа утверждена пользователем в редакторе версии **01432c7**. [Комплект художнику](../TECH_DOCS/README.md), [эталон и опоры](../TECH_DOCS/CHARACTER/BODY_STANDARD.md), [производство](../TECH_DOCS/CHARACTER/PRODUCTION.md), [порядок подключения](../TECH_DOCS/CHARACTER/DELIVERY.md).

## Что зафиксировано

Редактор использует `editorMotion.ts`, `editorReview.ts`, `editorHair.ts` и `AvatarPreview.tsx`. Их код, UI, тело и анимация при подготовке ТЗ не меняются. В `scripts/character/approved-snapshot.json` закреплены commit и SHA-256 ключевых исходников, включая материалы и общий адаптер. Экспорт отказывается молча принять изменённую основу.

96×128 на кадр; голова 40×40, ухо 5×10, кулачок 10×10. Четыре комплекции very-slim/slim/average/sturdy; мужской корпус прямоугольный, женские плечи уже только в S. Руки и ноги прямые, длины узел→конец 26/26, без вращения/сгиба. Нативный контур 2 px с открытыми внутренними стыками. Конкретная таблица ширин и координаты находятся в BODY_STANDARD; размеры новых файлов — в таблице TEMPLATE/EMPTY, не в старом модульном rig.ts.

Ожидание — два удерживаемых кадра по 500 мс: ноги неподвижны, корпус/голова опускаются на 1 px. Ходьба — четыре кадра **125/175/125/175 мс**, цикл 600 мс; корпус [0,-1,0,-1], голова неподвижна. Перенос ноги поднимает целую ногу на 6 px, другая опорная; кулачки отдельно смещаются, плечи/руки не вращаются. Волосы следуют постоянной опоре головы, не масштабируются по фазе.

A24 576×512 — внутренняя запечённая текстура проигрывателя, 2 idle + 4 walk, внутренние строки N/E/S/W. Поставочный статичный full имеет другой порядок S/E/N/W. Эти форматы не взаимозаменяемы. Художник A24 не делает. Четыре направления подготовлены независимо; mirroring возможен только в явно выбранном режиме симметричного источника.

## Как получены подложки

`scripts/character/artist-contract.ts` — отдельный authoring-контракт: размеры, опоры, порядок видов, зоны низа/волос. В браузерный редактор и старый импортёр он не импортируется. `export-avatar-tech.mjs` открывает локальный Vite и читает **тот же createEditorRig**, перехватывая готовые неизменные текстуры модулей и их целочисленные трансформации. Геометрия тела не рисуется заново отдельным генератором.

Экспорт изолирует браузер от реестра будущих импортированных вещей. Голова без временной причёски берётся из той же женской основы; её анатомия одинакова у обоих полов. На технической подложке нормализуются только цвета/временный внутренний шов рукава; силуэт, открытые стыки, внешняя обводка и посадка сохраняются. BODY_MALE/BODY_FEMALE показывают 4×4 статичных вида, MODULES — шесть частей в четырёх ракурсах. Это справочные схемы, не новая игровая графика.

У рукава/накладки руки холст **24×40**, опора (12,8): верх плеча y=2, низ руки y=34. Старый 24×32/(12,4) обрезал бы утверждённое плечо и не совпал бы с длиной. Корпус 56×52/(28,24) выровнен на (48,72). Низ 80×64/(40,20) сохраняет компактный формат, но оси ног S — 32/48, N — 48/32, профильной видимой — 42. Ладонь привязана к y=86, центр кулачка на 4 px ниже, стопа к y=110. Голеностоп и пятка в профиль подгоняются отдельно от центра обуви S/N.

У одежды допускаются перекрытия скрытых стыков. У женщины top_female — альтернативная посадка, не второй слой одежды. Цвета и четыре телосложения не требуют отдельных художественных файлов. Маски — пять серых индексов, контур 2 px; fixed-фурнитура RGBA; эффекты кожи могут иметь промежуточную alpha.

## Существующий импорт и следующий шаг

`character:import`, `modular/rig.ts` и `modular/render.ts` пока сохраняют **прежний** импорт/игровую геометрию. Их работоспособность для прежнего каталога не является доказательством поддержки нового комплекта. Старый валидатор отклоняет плоский контур 2 px, limb sampling использует 20/24, torso fit — прежнюю талию/плечи и y=70, разбор низа — прежние центры/экранный порядок. Одинаковый размер некоторых PNG не устраняет эти расхождения.

На этом этапе обновлены документы, подложки и инструменты экспорта; **редактор, импортёр, игра и карта не изменены**. Перед подключением первой поставки нужно адаптировать подготовку/подгонку слоёв к новому контракту и проверить отдельный комплект. Не исправлять новую графику путём возврата тела к прежнему rig.ts. Не запускать старый импортёр над новыми файлами с обещанием автоматической совместимости. Художественные исходники можно рисовать сейчас: их опоры и новая основа уже зафиксированы.

Требования к следующему подключению: оригиналы неизменны; совместимые IDs/AvatarConfig; отдельные N/E/S/W; правильные опоры, длины 26/26 и контур 2 px; полная проверка мужской/женской посадки и четырёх комплекций; при ошибке сохраняется последний рабочий результат. После этого — пробный импорт, сохранение/reload и публикация. Перенос утверждённого тела из редактора на завод — отдельная задача, не выполненная заменой документации.

## Проверки и воспроизводимость

```sh
npm ci
npm run art:build
npm run art:check
npm run typecheck
npm test
npm run format:check
npm run export:pages
```

Для art:build нужны Node 24, установленный Chromium/Playwright и Python 3 стандартной библиотеки для ZIP. Новых runtime-зависимостей нет. Скрипт сам поднимает и завершает локальный Vite. Не вызывает character:import и не записывает файлы приложения/карты.

В TECH_DOCS/CHARACTER — 38 пар TEMPLATE/EMPTY, две схемы тела, MODULES, палитра и единый ZIP. Технический manifest остаётся в `content/avatars/modular/template-manifest.json`: версия утверждения, хеши исходников/PNG, размеры, опоры и проверяемые позы. Художник JSON не редактирует. ZIP детерминирован, включает только активные документы/PNG и пустые папки сдачи с ITEMS.md, без приложения, исходных коллекций, node_modules или анимационных листов.

art:check проверяет исходные SHA-256, все PNG CRC/размеры/порядок/опоры, прозрачность EMPTY, согласованность ширин с редактором, фактическую финальную ширину ушей, локальные ссылки и полное совпадение ZIP с файлами комплекта. Для точности геометрии источником остаётся утверждённый renderer. Изменённая копия PNG или исходника вызывает ошибку, не молчаливую перегенерацию нового стандарта.

Старые игровые/Auth/RLS/импорт-тесты остаются обязательными для приложения. Техническая проверка комплекта не доказывает визуальную посадку ещё не нарисованной одежды, доставку OTP, готовность Supabase или мультиплеер. Исторические параметры 1 px, три комплекции, 8 fps, локти/сужение конечностей не являются новым художественным стандартом.
