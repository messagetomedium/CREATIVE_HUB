# Персонажи 2×: инженерный контракт

Актуально на 28 октября 2026. Художнику нужен только [TECH_DOCS](../TECH_DOCS/README.md). Здесь — устройство программы, проверяемые ограничения и воспроизводимость.

## Каноническая геометрия

`apps/web/src/avatar/modular/rig.ts` — источник FRAME, BODY_SHAPES, FACE_ANCHORS, поз, FPS и лимита кэша. `templates.ts` задаёт нативные холсты и опоры сменных слоёв. Рендерер, экспорт PNG и импортёр используют эти же данные. Тело перерисовано процедурной геометрией в новом разрешении; это не увеличенный старый PNG. Контур raster/polygon определяется по соседним пикселям и имеет толщину 1 native px, без обводки внутренних тональных переходов.

Фиксированы кадр 96×128, A24 576×512, опора (48,112), голова 40×40. Уровни комплекции вычисляются от худого факторами **1 / 1.16 / 1.32**, с целочисленным округлением; ширина конечностей квантуется к чётному пикселю, чтобы соседние комплекции не схлопывались при растеризации. Плечи 28/32/37, талия 18/21/24, таз 22/26/29, руки 10/12/14, ноги 12/14/16, полуинтервал ног 8/9/11 исходных px. Это ширина и поперечная посадка при сохранённом утверждённом росте, не масштабирование всей фигуры по X/Y. Голова, ладони и обувь не растут. Рука сужается к постоянному запястью 8 px, нога к голеностопу 10 px; импорт одежды использует те же локальные коэффициенты.

Состав рига: head, torso (с шеей/тазом), armLeft/Right, handLeft/Right, legLeft/Right, footLeft/Right. Внутренние joint — для поз и привязки ткани, не заказ художнику рисовать отдельно локти/колени. Ладони имеют простой выступ большого пальца, без отдельных фаз пальцев. Ботинок — целый неподвижный модуль относительно стопы.

Дыхание 2 fps: корпус/голова синхронно смещаются на 1 исходный px, стопы на полу. Walk 8 fps, четыре ключевых фазы: контакт, перенос, противоположный контакт, перенос. В профиле стопы перемещаются по X, переносимая нога поднимается; небольшой сгиб колена. Руки в противофазе. Корень руки движется только вместе с корпусом: независимой анимации плеч нет. Физическая скорость 168 world px/s и фиксированный шаг world-core сохранены.

Четырёхкадровая походка — стилизованная иллюзия шага. Строгое непрерывное закрепление стопы в мировых координатах при 168 px/s и 8 fps не доказано: между ключами персонаж проходит 21 world px. Утверждать biomechanical foot locking по этим четырём запечённым позам нельзя. Для строгой фиксации понадобится согласовать другое соответствие дистанции и фаз либо отдельную коррекцию контакта; текущий этап не меняет физическую скорость ради сокрытия этого ограничения.

## Цельные исходники и проекции — дополнение

Низ загружается одним PNG 80×64 на ракурс: pants/skirt/shorts × high/low. В layout.ts заданы bandTop=8, bandBottom=16, legSplit=24, shortHem=34, maxHem=50 и внутренний leg frame 32×40 с anchor (16,4). High даёт верхнюю поясную часть; low не создаёт её. У юбки основная нижняя часть остаётся цельной. У брюк/шорт нижняя часть разбирается на мост/таз и две штанины, профильная видимая штанина переиспользуется для дальней ноги. Выход из допустимой области вызывает ошибку, не молчаливую обрезку. При нейтральной позе опоры всех частей получаются из того же whole-sheet шаблона.

Причёски short 96×96 и long 96×112 содержат голову/шею/плечи/грудь. layout.hairLayer определяет перед/зад, теми же цветами размечен TEMPLATE: N весь front; E ниже y54 front при x≥48, W наоборот; S ниже y54 передними являются полосы [28,40) и [56,68), остальное back. На голове y<54 рисунок front, окно лица оставляет художник. Разбор — точное распределение исходных RGBA между двумя слоями, без перекраски/удаления пикселей. Произвольную невидимую глубину одного PNG невозможно восстановить однозначно; пределы зон и необычный дизайн проверяются глазами. Не выдавать эту схему за универсальное семантическое распознавание волос.

Единый details 64×64 показывает голову и шею; отдельные шаблоны шапок/украшений/верхних аксессуаров не нужны. Лицевые эффекты front используют ту же однокадровую подложку, что details sym1, но другую логику импорта. Глаза и рот имеют отдельные фронтальные шаблоны. E/W глаз — соответствующие половины с фиксированным переносом; разные глаза сохраняются. Рот делится около bbox-центра, профиль переносится и остаётся непустым даже при 1 px. У накладок лица — соответствующая половина, у переносицы центральная область; N пустой. Это двумерная адаптация, не 3D-лицо: необычные рисунки требуют визуальной приёмки. Обувь pair — один ботинок S/E/N, W и вторую стопу готовит программа.

Шея — часть генерируемого корпуса за головой: боковые линии x44/x51 от y51, нижняя заливка переходит в корпус без нижней линии. Экспорт головы/шеи вызывает ту же renderNeck. Увеличение числа художественных модулей художнику не требуется.

## Масштаб и DPR

Phaser Canvas получает текстуру 576×512 и sprite scale=0.5, display size 48×64, origin (0.5,0.875). Коллизии/feetDepth/геометрия карты не изменены. Phaser 3.90 не имеет GameConfig.resolution: используется нативный canvas `logicalSize×min(DPR,2)`, CSS logicalSize и соответствующий zoom камеры. ResizeObserver пересчитывает размеры и отключается при destroy. Smoothing выключен, pixelArt/roundPixels включены. Обычный React preview сохраняет прежний визуальный размер и учитывает DPR; режимы 1×/A24 показывают исходную геометрию.

На **DPR2** при обычном масштабе один исходный пиксель соответствует одному физическому. На **DPR1** исходный пиксель занимает 0.5 физического: невозможно одновременно показать каждый такой пиксель и сохранить прежний размер без сглаживания/изменения толщины. Nearest сохраняет резкость, но мелкие элементы могут выпадать/неравномерно дискретизироваться. Исходник не утолщается и масштаб мира самовольно не увеличивается. Практический режим проверки всех деталей — 1× в конструкторе (96×128) или DPR2. Если понадобится одинаковая визуальная толщина на DPR1, отдельное согласованное решение — производная контурная LOD-текстура или увеличенный просмотр; в текущем результате такой изменённый художественный контур не выдаётся за неизменный оригинал. Проверки DPR подтверждают размеры, sampling и отсутствие ошибок, а не гарантируют идентичность каждой детали на разных экранах.

## Импорт

`npm run character:import` → `scripts/character/pipeline.ts`. Стандартные параметры задаются категорией/суффиксами; ITEMS.md — названия и исключения. Новые имена category_template_symmetry_01.png. full = S/E/N/W; pair = S/E/N; details sym1 = один S для всех; sym2 = S/E, N=S и W=отражённый E; front = один фронт лица. Старые FULL/SYM_NES/SYM_ES читаются только для совместимости с прежним порядком, в актуальной художественной поставке их нет. Проверяются размер до распаковки, PNG CRC, alpha, палитра, граница клетки, пустой обязательный вид, явный двухпиксельный плоский внешний контур, метаданные/дубликаты/конфликты слотов. Недопустимые цвета не нормализуются молча. Автомат не может понять смысл ракурса, точную художественную посадку или произвольное перекрытие; это проверяется визуально.

Рабочие RGBA-копии разворачиваются в N/E/S/W; оригиналы CHARACTER неизменны. Детерминированные SHA-имена содержимого, registry `parts.json`, `import-manifest.json`, миниатюры. Неизменённый предмет пропускается, сохранённый hash/оригинал проверяется тестом. Исправление затрагивает один item; старая рабочая версия сохраняется при ошибке новой. Удалённый источник удаляет собственные неиспользуемые производные, остальные предметы остаются. DEBUG_REPORT содержит только актуальные критические ошибки без временных меток/успешных списков. Повторная попытка после исправления очищает запись.

Запись в manifest/registry выполняется через временный файл и rename. Отдельные валидные предметы могут импортироваться при ошибке другого; exit code 1 сообщает о непринятых файлах. Перед публикацией исправить отчёты. Не сканируются symlink как художественные PNG. Размер входа ограничен 8 MiB, размеры canvas проверяются до decode. JSON художник не пишет.

Каталог и IDs сохранений прежние. Веб-интерфейс статически читает импортированный manifest; после импорта нужен content build и перезагрузка/новая публикация. Ключ кэша включает hash-URL деталей, поэтому смена рабочего PNG не возвращает прежнюю текстуру. Голая кожа под одеждой остаётся основой; зарегистрированная обувь/перчатка скрывает соответствующий базовый модуль. Порядок проходов и parent соблюдается относительно корпуса/конечностей, default-одежда отключается при подключении настоящего предмета.

## Генерация и проверки

```sh
npm ci
npm run character:import
npm run art:build
npm run art:check
npm run typecheck
npm test
npm run test:e2e
npm run format:check
npm run export:pages
```

art:build поднимает локальный Vite, использует тот же browser renderer и завершает сервер. Native TEMPLATE/EMPTY — в TECH_DOCS/CHARACTER/TEMPLATES; только маленький технический manifest — в content/avatars/modular/template-manifest.json. Внутренние просмотры A24/поз/пропорций — `.cache/character-review`, не в художественной поставке и не в игровом каталоге. Старые архивы, ORA/V3/A24 и дубли ТЗ удалены из активного дерева; историю сохраняет Git. Канонический первоначальный тест волос перенесён в `content/art/source/hair-test-original.png`, индексированный runtime PNG сохранён; исходник пользователя `female-adult-test.png` не удалён. Legacy-адаптер волос делает рабочую 2× копию и уменьшает удвоенный внешний контур, не переписывая исходник.

Unit/integration проверяют импорт/отчёты/повторы/оригиналы/симметрию/маски/геометрию, браузер проверяет реальный PNG→CLI→слот→сохранение→Phaser на временном каталоге через управляемые JSON/PNG-ответы и удаляет его в finally; оригиналы репозитория тест не перезаписывает. Проверяются actual pixel widths трёх комплекций, постоянные головы/ладони/стопы, точки рукава/перчатки/обуви, source/atlas preview, DPR1/2 и resize. Старые игровые/Auth/RLS/сессии должны оставаться зелёными. Реальная доставка OTP этим этапом не проверяется.

Один A24 — 1179648 bytes RGBA (1.125 MiB), LRU 4 варианта — 4.5 MiB CPU-поверхностей, плюс активная Phaser texture/исходники. Это не общая память браузера и не замер FPS. Исходные PNG ограничены 16 записями. Во время проигрывания нет повторной сборки слоёв, тяжёлой физики волос или новых коллекций ассетов. pngjs — MIT authoring dependency, не browser runtime.
